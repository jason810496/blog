這次是我第一次去美國參加 Apache Airflow 的開發者大會 Apache Airflow Summit 2025，也是今年最忙碌的一週。同時擔任參與者、講者、一些議程的主持人，還有在會後參加 Airflow Contributor Workshop 幫助新手貢獻者入門。

在這週我需要準備 Databricks 的 Coding Interview 和 System Design Interview、研究所推甄資料、Airflow Submit 的內容與簡報，還有打包行李。在出發的前一天我都還沒準備好簡報，也還在寫推甄資料。甚至在出發前幾小時才寫完台大的推甄資料。在飛機上才在整理簡報內容。

到了美國的第一餐，我遇到快要所有在貢獻 Airflow 的面孔，包括 Jarek, Jens, Sharar, Elad，也有一起從台灣來的 Wei, TP 。

在 Day 1 的 Key Note，我們介紹了 Airflow 3 的新功能 TaskSDK。TaskSDK 解決了安全性、合規性、效能等問題，並且實現了 Client / Server 分離。使用 Execution API，可以讓使用者在不更新 Core Airflow 版本的情況下，更新最新的 TaskSDK。

其中有講到許多都是由台灣人主導的功能，例如在紐約唸書的 Roy 主導的 Internationalization 功能，讓 Airflow 支援多國語系。還有 Wei 和 GuangMing 主導的 Human-in-the-Loop 功能，讓使用者可以在工作流程中加入人工審核的步驟。還有我主導的第三方服務支援 External Event Driven Scheduling 功能，讓使用者可以根據外部事件來觸發工作流程。

同時還需宣布 Wei 成為 Apache Airflow 的 PMC 成員，這是台灣第二位 Apache Airflow 的 PMC 成員。還有現在台北的 GuangMing 拿到 Apache Airflow 的 Committer 身份。

在議程以外的時間就跟很多來自 Astronomer 的核心開源貢獻者交流，覺得有趣的一點是大家都跟 GitHub 的頭貼長不太像，一開始自我介紹需要先問別人的 GitHub Id 和頭貼長什麼樣子，才知道對方是誰。應該有蘇算大型網友見面會，畢竟原本大家都在線上互動、討論，這次是第一次面對面講到話。大家都很熱情，聊了很多 Airflow 的技術細節和未來的發展方向。

在 Day 2 的時候，我擔任了兩個議程的主持人，分別是 "Airflow 3 - An Open Heart Surgery" 和 "Uber AirLift to Airflow"。第一場講者分享
從 user 的角度用 OTel 看所有 span 去了解 Airflow Core 的運作，把 span 分類為 4 種 catagories。
經過 trace 來看 BashOperator，會發現需要 150+ function call, 超過 40 不同 function, 超過 25 個 module 介入, 5 個 component 在互動才有辦法完成一個 BashOperator 的 call。平常都是以貢獻者的角度去看 Airflow 的程式碼，這次從使用者的角度去看 Airflow 的運作，發現很多平常沒注意到的細節。

而 Uber 的 AirLift to Airflow 講者是很早期的 PMC 成員，他分享了 Uber 如何從 AirLift 過渡到 Airflow，並且使用 API gateway 來路由 Airflow 或 Piper，還有使用 Read Replica 來提升 Metadata DB 的效能。最後還有跟他請教他們目前開資料庫的規格，大小比我預期的小台但也夠支撐他們未來的 scale。

Day 3 的時候，我進行了自己的 talk 主要在分享貢獻 Airflow 的經驗，大概有 4~50 人參加，比我預期的多很多。講完之後還有一些人來問我問題，覺得很開心能夠幫助到其他想要貢獻 Airflow 的人。也還好這次準備簡報有用比較多具體該如何開始貢獻的例子，而不是分享故事。

這天中午跟從 San Francisco 特別來 Settle 參加的 JianHao，也是其中一個 OpenSource4You 的成員們一起聚餐，聊了很多關於開源還有目前美國的就業市場狀況。像是他遇到聯邦政府停擺，即使拿到 offer 也無法入職的狀況，對於簽證影響很大。還有目前 AI 對美國的經濟狀況和科技公司的裁員潮。

這次來參加 Airflow Submit 2025，讓我能夠當面與每天在線上碰面的貢獻者交流的機會，真的很難得也很開心。希望未來有更多這樣的機會能夠參加，並且繼續貢獻 Airflow，讓這個專案變得更好。
